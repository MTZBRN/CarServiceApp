## Exact representation difference

Source external-network entry:

```json
{"name":"fictional-network","external":true}
```

Actual Compose 2.38.2 `config --format json` entry:

```json
{"name":"fictional-network","ipam":{},"external":true}
```

Gate D's whole-dictionary equality rejected the additional empty IPAM object.
`validate_model()` now requires exactly one `workshop` network, its exact name,
literal boolean `external: true`, and only the name/external/ipam keys. IPAM must
be absent or exactly `{}`. Nonempty IPAM, null/list IPAM, creation options,
additional networks, wrong names, false/nonboolean external all remain refused.

Full old/new reproduction also exposed the next normalization issue: authored
`"bind":{"create_host_path":false}` becomes `"bind":{}`. This would have
failed immediately afterward as `unsafe-bind`. `native_models()` now first
authenticates and validates the authored old/new baselines, including their
explicit false flags. Only then does it restore omitted false values in native
output before running the same complete validators. Explicit true, malformed
binds, unexpected storage paths, mutable images or changes beyond storage are
not normalized away. The authored baseline contract remains strict.

Both actual normalized models now pass the candidate `native_models()` checks
locally. The cross-platform reproduction uses `--no-path-resolution` to keep
Linux storage paths lexical on Windows; the network insertion was also reproduced
without that option. This is real Compose parsing/validation, not a Docker
lifecycle result. The existing hosted harness still uses native path resolution.
