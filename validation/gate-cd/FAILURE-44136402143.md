# First Docker run: evidence, fixture correction and limits

Inspected the complete job log for [run 44136402143, attempt 1](https://github.com/MTZBRN/CarServiceApp/actions/runs/44136402143),
job 134227013340, main commit `8342c8126955e2592bee6d35a43e2212d2962db1`.
Gate C's 32 and Gate D's 34 unit tests passed. Docker 28.0.4 and Compose 2.38.2
were installed; the private daemon loaded the fixture image. About two seconds
later C's Docker driver printed FAIL. No recovery PASS was printed; D was not
reached. Cleanup succeeded. The run has no uploaded artifacts.

## What is established

The failure details were discarded by the wrapper: `subprocess.run(check=True)`
raised before reading `gate-c-docker-report.json`. The test catches its exception,
writes that report privately and prints only FAIL. Consequently the exact first
exception from that historical run is **not recoverable from retained evidence**.
Do not describe an inferred exception as an observed log entry.

A concrete, reproducible fixture incompatibility exists: both harnesses create
`--internal` bridge networks, but the candidate compares each running endpoint's
Gateway to the nonempty network IPAM Gateway. Docker 28.0.4's bridge
[Join implementation](https://github.com/moby/moby/blob/v28.0.4/libnetwork/drivers/bridge/bridge_linux.go#L1374)
sets an endpoint gateway only for non-internal networks. The network IPAM gateway
and an internal container's empty endpoint gateway are distinct facts.
The regression executes the actual candidate metadata functions against that
explicit synthetic shape and reproduces `network-address-changed`.
This is a source-backed diagnosis consistent with the early failure, **not a
reproduction of the lost runner report**; another hosted run is required.

## Narrow correction

Operational `gate-c.py` (both copies), `gate-d.py`, storage helper and unit suites
are unchanged. The shared fixture adapter wraps inspect only for the disposable
C driver and D harness. Before each inspection it calls the candidate's original
network identity/IPAM/peer check with the original gateway, then requires the
network's actual Internal field to be exactly true. Only during the original
endpoint inspection does it require an exactly empty gateway, restoring the
original IPAM expectation in `finally`. Wrong IDs, image, IP, static-IP intent,
peer set, IPAM gateway and public ports continue to fail. A non-internal network
is refused. No recovery authorization or source checks are altered.

The driver also records fixed RuntimeError refusal codes. The wrapper prints
allowlisted report status/checks/failure fields before propagating nonzero exit,
and refuses a non-PASS report even if a child returns zero. It still stops before
D on any C failure. No raw environment, database values or arbitrary exception
messages are printed. The private daemon and cleanup behavior are unchanged.
