## Exact failing check and defect

`recover()` in `gate-c.py` obtains two `check_pair(stopped=True)` dictionaries two
seconds apart and requires `first == second`. This is before `source_matches()`
or fresh source capture. SQLite is not involved at this failure point; the Docker
driver explicitly mocks source/custody inputs for its lifecycle-only scope.

The backend has two bind mounts. `inspect()` already validates those mounts using
sorted tuples, but returned Docker's raw `.Mounts` list in the snapshot. Docker
28.0.4 [GetMountPoints](https://github.com/moby/moby/blob/v28.0.4/container/container_unix.go#L398)
appends entries from a Go map without sorting. Two equivalent inspect responses
can therefore differ only in mount array order. Python list equality then reports
the stopped state as changed. The regression explicitly reverses the two mounts,
reproduces the old unequal snapshots, and proves the corrected snapshots equal.

Frontend-only recovery skips the two-stopped-snapshot/source-verification branch;
it instead requires the backend to remain running, healthy and at its original
start timestamp. The printed recovery PASS belongs to that completed frontend
case, not the following both-container case and not the VPS.

Evidence boundary: the failed job records the refusal code but not the two
snapshot values. Mount ordering is a confirmed source-level defect and reproducible
cause of exactly this failure; the historical differing field cannot be proven
from the retained log. No health or endpoint transition is assumed or suppressed.

## Minimal operational correction

Canonicalize the **full mount dictionaries** by Destination on return from
`inspect()`. Do not drop fields, deduplicate entries or normalize values. Source,
destination, type and RW admission remain exact. Differences in Propagation,
Mode or any other returned mount property still make snapshots unequal.
The two samples, delay, exact equality, start/finish timestamps, identity/network/
state checks, source integrity, custody/approval and recovery sequencing remain.
No retry, extra sleep, ignore-health rule or force-pass is introduced.

If equality still fails, the RuntimeError now identifies only fixed service and
field names, e.g. `stop-state-not-stable-backend-mounts` or
`stop-state-not-stable-backend-started-at`. No values/paths/IDs/rows/environment
are printed. The existing Docker report and wrapper propagate these sanitized
codes and continue to fail closed before D.

This changes both operational C copies, and changes D only to bind the new C
fingerprint. Both manifests, their verifier pins, operator launcher hashes/lengths,
hash-labelled filenames and current inventory are updated together.
